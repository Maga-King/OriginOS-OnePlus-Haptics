# 长震动提前停止的修复

`0.3.0-demo2` 在实际铃声测试中出现约半秒到一秒后停止的问题。本版 `0.3.0-demo3` 修改流式输出的补数据策略，没有改变波形映射或输入法、AI 唤醒的调校。

原来按样本时钟限制提交频率，会让驱动的 FIFO 补数据中断遇到空槽。实际 Qualcomm 驱动先检查槽位长度，再判断状态，空槽会触发结束工作。此外，驱动消费完槽位时先写 INVALID，再清零 length；用户态仅等待 INVALID，可能在清零完成前重写该槽位。

修复后使用驱动槽位作为背压，不再人为延迟补数据；复用槽位前同时等待 INVALID 和 length=0。直接 RTP 输出也使用同样的槽位交接条件。正常按键仍走此前的直接输出路径。

开发测试已加入 INVALID 与 length=0 分两步交接的模拟。波形、HE、队列、混音与 RTP 边界测试通过；765 个场景的输出摘要保持一致。实机诊断中的 3 秒波形返回约 2993 ms，短触感取消与长会话取消也完成。程序与内核记录不足以代替用户复核，通知和铃声的实际手感仍需确认。

这次只修复长波形输出，没有把插件改成新的框架会话调度器。插件 0.1.1 仍只补发通知期间被优先级拒绝的部分短触感，铃声期间的请求仍不在其范围内。双逻辑波形最终合成为一路物理 PCM 输出，不能因此说所有请求都已获准进入混音。

本次通知选择项记录还出现 IGNORED_APP_OPS，抓取时 zen_mode=1。该记录属于进入 HAL 前的框架限制，应在明确勿扰和通知权限状态后再测试；本版不会绕过这些设置。
